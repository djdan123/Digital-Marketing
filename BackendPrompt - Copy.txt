# Vision du projet

Le projet consiste à créer une plateforme numérique de gestion de publicité en ligne permettant aux entreprises, particuliers et organisations de diffuser facilement leurs annonces sur différents médias (radios, télévisions, sites web, réseaux sociaux, panneaux LED, etc.) à partir d'un seul espace.

Aujourd'hui, dans de nombreux pays, la réservation des espaces publicitaires se fait encore de manière manuelle : appels téléphoniques, échanges WhatsApp, déplacements physiques, documents papier et paiements séparés.

Ce processus entraîne :

* une perte de temps ;
* des erreurs dans la programmation des diffusions ;
* un manque de transparence sur les tarifs ;
* une difficulté à suivre les campagnes publicitaires ;
* une mauvaise communication entre les annonceurs et les médias ;
* une gestion administrative complexe.

Cette plateforme a pour objectif de digitaliser complètement ce processus.

---

# Solution apportée par la plateforme

La plateforme permettra aux entreprises et particuliers de :

* créer un compte annonceur ;
* publier des annonces publicitaires ;
* importer des fichiers audio ;
* importer des vidéos ;
* importer des images ;
* rédiger un texte publicitaire ;
* choisir le média de diffusion (radio, télévision, site web, réseau social ou panneau LED) ;
* consulter les tarifs avant la réservation ;
* choisir une date et une heure de diffusion ;
* sélectionner le nombre de passages ;
* effectuer le paiement en ligne ;
* suivre l'état de leur campagne en temps réel ;
* consulter les statistiques de performance ;
* télécharger leurs factures ;
* accéder à l'historique complet de leurs campagnes.

L'objectif est de centraliser toutes les opérations liées à la publicité sur une seule plateforme.

---

# Fonctionnement général

Le fonctionnement de la plateforme suit le cycle suivant :

1. Le client crée un compte.
2. Il complète son profil.
3. Il crée une campagne publicitaire.
4. Il ajoute une ou plusieurs publicités.
5. Il téléverse les fichiers nécessaires (audio, vidéo, image ou texte).
6. Il choisit un ou plusieurs médias.
7. Il sélectionne une date et une heure de diffusion.
8. Le système calcule automatiquement le coût selon les tarifs configurés.
9. Le client effectue le paiement.
10. L'annonce passe au statut **En attente de validation**.
11. L'administrateur vérifie le contenu.
12. Si l'annonce est conforme, elle est approuvée.
13. Le responsable du média programme la diffusion.
14. La publicité est diffusée selon le calendrier prévu.
15. Une preuve de diffusion peut être ajoutée.
16. Les statistiques de campagne sont mises à jour.
17. Le client peut consulter les résultats et télécharger ses rapports.

## 2. Client (Annonceur)

Le client représente une entreprise, une organisation ou un particulier souhaitant diffuser une publicité.

Il peut :

* programmer les horaires ;
* modifier un planning si nécessaire ;
* confirmer qu'une diffusion a été réalisée ;
* téléverser une preuve de diffusion ;
* consulter son calendrier de diffusion.

# Architecture

Respecte intégralement la structure déjà définie.

Ne modifie aucun nom de dossier.

Ne change aucune convention de nommage.

Tous les fichiers doivent être créés exactement dans leur emplacement prévu.

Aucune logique métier ne doit être placée directement dans les Controllers.

Les Controllers doivent uniquement :

* recevoir la requête,
* appeler le Service,
* retourner la réponse JSON.

Toute la logique métier doit être dans les Services.

Les Repositories doivent uniquement communiquer avec les Models.
